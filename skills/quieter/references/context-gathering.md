# Context Gathering Protocol

Protocol for assessing visitor mode and intent before refining an interface to be quieter.

---

## Visitor Mode Classifications

Every UI has a primary visitor mode that determines what "quieter" means in practice:

### 1. Persuade & Experience (Marketing, Landing Pages, Portfolios)
- **Goal**: Communicate value, build trust, guide to action.
- **Quieter Implementation**:
  - More restrained, curated color palette.
  - Increased whitespace and typographic breathing room.
  - Reduced drama while preserving the brand's unique point of view (POV).
  - High-craft display typography with solid ink.

### 2. Operate & Read (SaaS Apps, Dashboards, Developer Tools, Docs)
- **Goal**: Complete tasks efficiently without cognitive fatigue.
- **Quieter Implementation**:
  - Minimize visual noise: flat cards, subtle borders, muted status indicators.
  - Low-motion interface: transitions are nearly invisible utilities.
  - High information density with clear typographic hierarchy.
  - The UI disappears into the background so the user's data and tasks take center stage.

---

## 4 Context Questions (Clarify Before Refinement)

Before making edits to calm an interface, establish:

1. **What is the primary user task or message?** (Ensure changes sharpen this message rather than dulling it).
2. **Who is the audience?** (Developer/operator vs consumer/creative).
3. **What elements are already working effectively?** (Protect high-performing CTAs and core recognizable brand anchors).
4. **Where is the greatest source of visual friction?** (Excessive color saturation, chaotic spacing, overwhelming motion, or container clutter).
